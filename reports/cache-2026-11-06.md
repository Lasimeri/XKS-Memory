# Tier-1 record cache measurements, 2026-11-06

Rule: capacity = ceil(records / 4), 25 % of the store (project direction). Read-through, CLOCK eviction, open-addressing index (Fibonacci hashing, linear probing, backward-shift deletion), evicted on delete, resized whenever the record count changes.

## Correctness

- `tests/test_cache.c` 175/175: capacity 25 for 100 records; sequential scan leaves the last 25 resident (re-read = 25 hits); deleted records never served; returned copies independent of the cache; capacity 26 at 104 records, 19 at 74 with immediate eviction; reopen starts empty with capacity from the stored count; 3,000 random gets and deletes against an oracle: 0 wrong results, 0 capacity violations.
- All tests pass under AddressSanitizer, UndefinedBehaviorSanitizer and LeakSanitizer (`build-asan`, `-fsanitize=address,undefined -fno-sanitize-recover=all`).

## Latency

Command: `build/bench_get STORE 200000 0` (uniform ids) and `... 200000 80` (80 % of gets to the first 20 % of ids), store of 100,000 memories from `bench_insert` (capacity 25,000), two runs each. Ryzen 7 5800X, SQLite 3.54.0, the 78 MB store file warm in the OS page cache (misses are SQLite best case; cold-disk misses not measured).
