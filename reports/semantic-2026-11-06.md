# Count-based semantic model, first measurements, 2026-11-06

No neural model: co-occurrence (harmonic window 5, deterministic subsampling t = 1e-4) -> PPMI with context distribution smoothing (0.75) -> randomized SVD (rank 128, oversampling 16, 4 power iterations, CholQR2, Jacobi) -> word vectors (U + V) Sigma^0.5, row-normalized -> SIF memory vectors (a = 1e-3) minus the first principal component (Levy et al. 2015; Arora et al. 2017; Halko et al. 2011; sources in docs/RESEARCH notes).

## Build on the private-notes store (361 notes, 2,856 memories)

Command: `build/xksm semantic STORE` (CPU, 8-thread pool, Ryzen 7 5800X).


- The semantic vectors carry real signal (term-matching queries: recall@1 0.840 alone) but do not beat BM25 on paraphrases (recall@10 0.320 vs 0.440); fusion is about equal to BM25 alone.
- Diagnosis: of the 139 distinct words in the paraphrase queries, 124 are in the model vocabulary, but the 15 missing ones are the content words that carry the questions (196 query tokens, 181 known, the known ones mostly function words). Distributional statistics cannot relate words the corpus never contains.
- The missing words are of two kinds: morphological variants of words the notes do contain (addressable with subword composition, no external data) and true synonyms (need general-language text).
- Tuning was not done; with 25 paraphrase queries and no held-out set, any tuning would fit this query set.

## OpenCL GPU randomized SVD

Profile of the CPU SVD (3.32 to 3.33 s, two runs): sparse multiplies 0.200 s (6 %), CholQR2 orthonormalization 2.661 to 2.664 s (80 %), final projections and Jacobi about 0.46 s (14 %). Offloading only the sparse multiply would have saved at most 6 %, so the whole randomized SVD runs on the device (`backends/opencl/rsvd.cl`, `ocl_rsvd.c`): CSR x dense, partial Gram matrices (f32 over 256-row chunks, summed in double on the host), and tall-by-small multiplies; Y, Z and B^T stay in device memory; per orthonormalization only l x l data crosses PCIe (Cholesky and R^-1 in double on the host). Same Gaussian sketch as the CPU path.

Parity (`tests/test_ocl.c`, 4,000 x 3,000 sparse matrix with a decaying spectrum, k = 32): singular values GPU vs CPU max relative difference 2.52e-07; 13 well-separated singular vectors agree (|cos| >= 0.999).

Build time on the private-notes store, `build/bench_semantic STORE 3`, CPU (8-thread pool) and GPU (RTX 3090 Ti, OpenCL 3.0, NVIDIA 615.78.08) interleaved:

## Static embeddings from the model weights (no forward pass)

`benchmarks/static_gguf.c`: own GGUF parser (mmap), Unigram (UGM) Viterbi tokenizer over the model's 250,048 pieces and log-probability scores, lazy dequantization of only the used token-embedding rows (F32, F16, Q6_K as in ggml's `dequantize_row_q6_K`), SIF pooling with a / (a + exp(score)), first principal component removed. Tokenizer agreement with llama.cpp on all 2,856 memories: 2,834 identical (99.2 %), 99.59 % of token positions equal (difference: SentencePiece's NFKC map is not applied). 15,457 of 250,048 rows used (47.5 MB dequantized instead of 768 MB).

Reading: the static table performs poorly (paraphrase MRR 0.044, below the count-based model's 0.192) and FP32 gives the same result as Q6_K to three decimals, so quantization is not the cause. A transformer's input embeddings are keys refined by the attention layers; pooled without those layers they carry little sentence meaning. Distilled static vectors (one forward pass per vocabulary token, as Model2Vec does) would be the weights-based route with evidence behind it; not done.

The mean cosine between 2,000 fixed token pairs fell from 0.3110 to about 0.000, but retrieval did not improve: anisotropy is not the cause.

Nearest neighbours inside the tables (`XKSM_NEIGHBORS`):

- distilled: disk -> Disk, disk, диск, Disc, disc, 디스크; slow -> Slow, slowly, langsomt, 慢, медленно; memory -> Memory, memória, memoria, paměť, mémoire (cosine 0.74 to 0.98).
- raw token_embd: slow -> Slow, quick, speed, slowly, low; memory -> Memory, memorie, memória, memori, memoria, storage, battery, knowledge (0.55 to 0.80).

Reading: the tables are aligned and meaningful (no pipeline error), but the multilingual model maps a token seen alone to a language-independent identity: neighbours are translations and casings, not related concepts. Pooled, such vectors act as a cross-lingual soft keyword match and cannot relate different words of a paraphrase; the model's paraphrase ability comes from attention composing tokens in context, which a static table cannot keep. On this task the count-based model trained on the notes themselves (paraphrase MRR 0.192) remains the best model-free option; the full model with BM25 (0.404) is the quality ceiling measured here.
